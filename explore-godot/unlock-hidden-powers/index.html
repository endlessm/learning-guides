Jump to _physics_process()

Godot calls _physics_process() repeatedly while your game runs, 60 times per second by default. It helps handle things like character movement and collisions. In this script, it's also where you'll find the lines that activate your character's special abilities.

  1. With player.gd open, find the Filter Methods panel at the bottom-left of the Script editor, under the list of scripts.
  2. This panel lists every function in the script. Scroll through the list, or type physics into its filter box, to find _physics_process.
  3. Click _physics_process. The editor jumps straight to that function.
  4. Read down through the function until you see a comment that names a special ability, such as Remove the '#' below to enable the glide special ability.
  5. Directly beneath that comment is the switched-off function call. Together they look like this:
    # Remove the '#' below to enable the glide special ability #_glide()

Leave the line as it is for now. You'll make the change in the next step.

Another way: search with Ctrl+F
Press Ctrl+F (Cmd+F on Mac) and search for #_glide(), including the #. A shorter search like _glide also finds other lines, such as func _glide(). That's the function definition, where the glide code itself is written, and you don't need to change it. The line you change is the commented-out call inside _physics_process().
// STEP_03

Now turn the ability on

Here's the line you found in Step 2:

# Remove the '#' below to enable the glide special ability #_glide()

In GDScript, a line starting with # is a comment — the computer ignores it. Right now there’s a # in front of _glide(), which is why the ability doesn’t work. Remove the # to turn the ability on.

Try it here first. This button only changes the example on this page. It doesn't change your Godot project.

GLIDE ABILITY: DISABLED
# Remove the '#' below to enable the glide special ability #_glide()

With the # in front, Godot skips this line entirely. The glide ability never runs.

Now do it in Godot

  1. Go back to player.gd in Godot.
  2. Delete only the # in front of _glide(). Leave the spaces before it alone, because GDScript uses indentation to know which lines belong together.
  3. Save the script with Ctrl+S (Cmd+S on Mac).
  4. Run the game: press F5, or click the ▶ play button in the top-right corner of the editor.
  5. Test it: jump, then hold the jump button while you're still in the air. You should fall slowly with a glide sound. That's your first unlocked power.

Almost every programming language lets you leave notes in your code that the computer ignores — called comments. Programmers use them to explain what code does, mark things to fix later, or label sections so other people (and their future selves) can understand the file.

In GDScript, a comment starts with #; everything after it on that line is for human eyes only. Comments have a useful side effect: if you put # in front of a line of working code, that whole line becomes a comment too — so it stops running. Programmers call this "commenting out" code. It’s a fast way to disable a line without deleting it — great for testing, experimenting, or hiding features until they’re ready, which is exactly what your game is doing.

The lines you’re unlocking, like _glide(), are called function calls — short instructions that trigger a "recipe" of code defined elsewhere in the script. The # in front of each call disables that trigger. Remove it, and the call runs.

Unlock the rest

Phase, Shrink and Teleport work the same way: in _physics_process(), find the comment for the ability, delete the # from the call beneath it, then save and test. Glide is in the list too, so you can check it off. Clicking a card only marks it done on this page. It doesn't change anything in Godot.

You might have noticed something curious. The Input Map doesn't say "the up arrow makes the player jump." Instead, it says "the up arrow triggers an action called player_1_jump." Why the extra step?

Because that middle step — the named action — gives you flexibility you'd never get otherwise. Click any key below to see what happens:

Three keys all trigger the same player_1_jump action — keyboard, spacebar, gamepad. The code only ever asks "did player_1_jump fire?" It doesn't care which key was pressed. That's why Player 2 can use W while Player 1 uses Up: the code is identical, only the action name differs.

Bottom line: this design lets one piece of code work for any key, any controller, any player. You'll see it everywhere in Godot.

// STEP_05

Four skills you'll use again

None of these are specific to glide or phase. You'll use them again and again while modding a game:

  1. Landmarks help you find your way around a script. Use Filter Methods to jump to a function like _physics_process(), or Ctrl+F to find an exact line.
  2. The # switches a line of code on and off. Adding it disables the line; removing it enables it. Leave the indentation alone.
  3. The Input Map shows which input does what. Open Project → Project Settings → Input Map, then search for an action and expand it.
  4. One change at a time. Edit, save, test, repeat, so you always know which change caused which result.
